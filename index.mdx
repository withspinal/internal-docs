These are Spinal's internal engineering docs: the systems we run and the procedures we
follow to run them. If you are new, read this page, then open the fleet overview.

## What is here

The **Spinal Fleet** tab documents spinal-fleet, the control plane for our private SaaS
deployments. Each enterprise customer gets a full Spinal stack in their own Azure tenant,
deployed and operated from GCP through Azure Lighthouse. The tab has two groups.

- **Operating the fleet** is the runbooks: how a deployment works, how to launch a new
  customer from nothing, and how to offboard one. Follow these top to bottom while you do
  the task.
- **Deep dives** explain the parts the runbooks depend on: the fleet identity, Auth0,
  secrets, Lighthouse's limits, naming limits, and the local dev loop. Read these when a
  runbook step surprises you or fails.

## Adding or changing a page

The site is built with Mintlify from the
[withspinal/internal-docs](https://github.com/withspinal/internal-docs) repo. Pages are
MDX files, navigation is in `docs.json`, and a push to `main` deploys to
internal.docs.withspinal.com.

To preview a change before you push, install the Mintlify CLI and run it from the repo
root:

```bash
npm i -g mint
mint dev
```

The preview is at `http://localhost:3000`. Before you open a PR, run the review pass in
`.claude/skills/doc-writing/SKILL.md`. The bar is that a new engineer reads the page once
and can act.
